# Golden fixture matrix — (4 dirs × plain/tools/stream)

The cross-format corpus: every translation leg of the
4 direction pairs (face wire × upstream wire) × 3 modes, committed byte-for-byte.
Janus always canonicalizes (the byte-forward fast path was deferred), so even
the passthrough cells (`oo`, `aa`) go wire → canonical → wire; these fixtures document
the *actual canonicalized shape* and the tests assert it byte-for-byte.

| Dir | Face (client wire) | Upstream wire | Translation |
|---|---|---|---|
| `oo` | OpenAI `/v1/chat/completions` | OpenAI-compatible (DeepSeek) | passthrough (canonicalized) |
| `oa` | OpenAI | Anthropic `/v1/messages` | cross-format |
| `ao` | Anthropic | OpenAI-compatible | cross-format |
| `aa` | Anthropic | Anthropic | passthrough (canonicalized) |
| `ro` | OpenAI Responses `/v1/responses` | OpenAI-compatible (DeepSeek) | cross-format |
| `ra` | OpenAI Responses | Anthropic `/v1/messages` | cross-format |

The `ro`/`ra` legs reuse the SAME canonical artifacts and
byte-copy the sibling faces' upstream + outbound-request legs (one canonical, three
wires — the cross-face proof). Their inbound legs are hand-authored Responses wire
(the face is decode-only for requests); their outbound response/stream legs are the
Responses encode with the deterministic matrix clock (`created_at` pinned).

## Provenance (honest)

- **Upstream-shaped legs (`upstream.response.json` / `upstream.stream.sse`) are
 hand-authored from the documented wire shapes — NOT verbatim real-upstream captures**
 (the C1 discipline). The 12 upstream legs are copied from the committed `openai/`
 and `anthropic/` corpora where shapes match (`oo`/`ao` ← `openai/`;
 `oa`/`aa` ← `anthropic/`) and hand-authored otherwise (the tools responses). A real
 capture (the `captureFixtures` task with a live key) replaces them; the matrix tests
 pin the committed bytes, not their origin, and the gate's live SDK smoke is the
 real-bytes arbiter.
- **Everything else is machine-emitted.** `MatrixFixtureGeneratorTest`
 (`@Tag("capture")`, network-free) reads the upstream legs + `MatrixCanonicals` (the
 canonical records) and writes every Janus-generated leg + `canonical/*` in place:
 `./gradlew :janus-core:captureFixtures`. `GoldenMatrixTest` then asserts the
 regenerated bytes are identical, so a codec change that alters wire bytes fails CI.
- CI never touches the network (AGENTS.md): capture/generator are `excludeTags
 'capture'` in the default test task.

## Canonical intermediates (`canonical/`)

Byte-golden under `JsonSupport.mapper` serialization — the single source the
generator and the golden/property suites read. The canonical model is OpenAI-idiomatic
(the convention); `max_tokens` is carried explicitly (4096 — the Anthropic codec's
default) so the Anthropic wire round-trips idempotently. The canonical stream chunks are
the exact decode of 's `openai/chat.stream.sse` (8 chunks: role, 5 content deltas,
finish, usage — `stream_options.include_usage` terminal chunk).

## Per-cell artifacts (4 per cell)

`inbound.request.json` (face codec), `outbound.request.json` (upstream codec),
`upstream.response.json`/`upstream.stream.sse` (hand-authored upstream shape),
`outbound.response.json`/`outbound.stream.sse` (face codec). `inbound.request.*` is
byte-duplicated across same-face cells (`oo`≡`oa`, `ao`≡`aa`) deliberately:
self-contained cells, manifest-guard philosophy, generator-emitted.

## Equality levels

- **Byte-golden — Janus-generated legs:** `outbound.request.json`,
 `outbound.response.json`, `outbound.stream.sse`, `inbound.request.json`.
 `encodeX(canonical)` must reproduce the committed bytes exactly, and
 `decodeX(inbound)` must yield the committed canonical. The chosen shapes are
 round-trip idempotent (rule: exactly one system message, no `system`-field +
 `SystemMessage` duplication, `max_tokens` explicit, no tool `description` in the
 golden set).
- **Semantic — upstream-generated legs:** decode → canonical → re-encode, then
 order-insensitive JSON-tree compare (`JsonSupport.treeEquals`; explicit null ≡
 absent). Values survive; positions do not.
- **Reference — errors:** parse + vocabulary assertions only (classification lives in
 's loopback tests).

## What Janus changes on the passthrough cells (pinned by `GoldenMatrixTest`)

- `oo`/`aa` requests: the outbound request is **byte-identical** to the inbound request
 for all three modes — the fixtures document the canonicalized shape as the wire shape.
 For the OpenAI passthrough this includes `stream_options.include_usage` on the stream
 request. The /adapter never adds it: `OpenAiCompatibleAdapter.withStream` only
 **preserves/passes through** `request.streamOptions` on the streaming path — so the
 `oo` stream cell documents a client that already requested `include_usage`, and the
 codec maps the canonical flag through to the wire.
- **D1 (fixed, test-first):** the corpus canonical carries `stream_options.include_usage`
 (OpenAI-idiomatic — the convention). recorded the codec's passthrough onto the
 Anthropic wire as a hand-off defect (real Anthropic rejects the field — 400
 `invalid_request_error`); stripped it in `AnthropicMessageCodec.encodeRequest`
 (documented non-idempotence), regenerated the `{aa,oa}/stream` request cells, and
 flipped the `GoldenMatrixTest` pin from presence to absence (the red hand-off test).
 The canonical still carries `stream_options` — only the Anthropic wire drops it.
- `aa` stream: the outbound stream is byte-identical to the upstream bytes **except the
 two usage frames** : the real-shaped
 upstream carries the prompt count on `message_start` (`{"input_tokens":14,"output_tokens":0}`)
 and `output_tokens` only on `message_delta`, while the encoder re-emits zeroed 0/0
 `message_start` usage (the canonical opener chunk carries no usage — the C01 merge
 delivers the prompt side on the terminal chunk) and the merged prompt-preserving
 `message_delta` usage (`{"input_tokens":14,"output_tokens":12}`). The "byte-identical
 passthrough" claim therefore holds for every non-usage frame only — usage frames are
 re-shaped by Janus (the old synthetic corpus, which carried `input_tokens` on
 `message_delta` and 0 on `message_start`, masked the C01 prompt-token drop). The stream-
 request leg carries no `stream_options` after D1 — pinned by the byte-identical
 `aa/stream/inbound|outbound.request.json` pair.
- `oo` stream: the outbound re-encode strips the upstream corpus's explicit
 `"finish_reason":null` members (`@JsonInclude(NON_NULL)` on the OpenAI DTOs) — the
 only byte difference, asserted value-preserving (tree-equal). No `[DONE]` on
 Anthropic-face streams; `[DONE]` terminal on OpenAI-face streams; `message_stop`
 terminal on Anthropic-face streams.

## Format-field notes

- Anthropic responses decode with `object` from the wire `type` (`"message"`), `created`
 0 (Anthropic has no timestamp) and the upstream's own `id` — the oa/aa cells assert
 these per-format fields explicitly and everything else record-equal.
- Anthropic streams merge the canonical finish + usage chunks into one `message_delta`
 chunk (8 content-bearing frames vs the OpenAI 8-chunk split; the message_delta carries
 `stop_reason` + `usage` together) and re-emit the OpenAI role chunk's empty content as
 an empty `text_delta` (the encoder's canonicalized shape — documented).
- **D2 (fixed, test-first):** the OpenAI-face outbound response previously re-emitted
 the Anthropic-derived canonical's format fields verbatim — `"object":"message"` on the
 `oa` cells (recorded it as the m1 hand-off; the pinned OpenAI Python SDK types
 `ChatCompletion.object` as `Literal["chat.completion"]` and rejects the leak). 
 normalized the OpenAI-face outbound `object` to the wire constant (`"chat.completion"`
 on responses, `"chat.completion.chunk"` on chunks) in `OpenAiMessageCodec`; the `oa`
 `outbound.response.json` cells regenerated (`created` stays 0 — a valid epoch-second
 int the SDK accepts, the codec's deterministic handling).

## C02 codec-review notes (pinned by `OpenAiRequestCodecTest` / `OpenAiChunkCodecTest` / `CrossFormatMatrixTest`)

- **Message `name` stays inside the message on the OpenAI leg.** The wire `name` is a
 legal per-message field (`user`/`assistant`/`tool`) with a canonical home
 (`UserMessage.name`/`AssistantMessage.name`/`ToolMessage.name`); the OpenAI codec
 re-emits it inside the message, never as a bogus top-level request field (strict
 OpenAI upstreams reject unknown top-level parameters). The Anthropic wire has no
 per-message name home — the value is dropped on the Anthropic leg (documented
 non-idempotence; the canonical `tools.request.json` message now carries `"name":null`).
- **Delta-level unknowns keep their position.** DeepSeek `delta.reasoning_content`
 (and any other delta-level unknown) rides `Delta.reasoning` and re-emits *inside* the
 delta — never hoisted to the chunk top level. The canonical
 `stream.chunks.json` deltas now carry `"reasoning":null`.
- **Anthropic-only `tool_choice_disable_parallel_tool_use` never reaches the OpenAI
 wire.** The OpenAI request encode strips the reserved extras key (the Anthropic codec
 consumes it into `tool_choice`; the OpenAI face has no equivalent).

## C03 codec-review notes (pinned by `OpenAiRequestCodecTest` / `ToolDefinitionTest`)

- **Tool definitions are `ToolDefinition`, not `ToolCall`.** The canonical `tools`
 array holds `ToolDefinition` records (`{type,name,description,input_schema}`, schema as
 a raw JSON string) while assistant-message `tool_calls` stay `ToolCall` invocations
 (`arguments` as raw JSON) — the two shapes are unrelated types, so a definition's
 schema can never be emitted as a tool-call argument. The regenerated
 `canonical/tools.request.json` carries the new shape; the wire bytes are unchanged
 (the codecs map `input_schema` ↔ `parameters`/`input_schema` objects exactly as
 before).
- **OpenAI `developer` role.** A `role:"developer"` message decodes to
 `DeveloperMessage` and re-encodes as `"developer"` on the OpenAI wire; the Anthropic
 leg merges its content into the top-level `system` field (LiteLLM
 `map_developer_role_to_system_role`). Never legal in a streaming delta.
- **`ao` streaming tool-call indices are tool-only.** The stateful Anthropic stream
 decoder renumbers content-block indices (text and tools share one counter on the
 Anthropic wire) into a tool-only 0-based space, so an ao passthrough emits contiguous
 OpenAI `tool_calls` indices. The stateless per-event decode keeps the verbatim block
 index (documented divergence, pinned by `AnthropicChunkCodecTest`).

## Coordinated-edit spots

The manifest guards pin the exact file sets (`MatrixManifestTest`,
`AnthropicFixtureManifestTest`, 's `FixtureManifestTest`); `GoldenMatrixTest` pins
the per-cell bytes; `FixtureIdempotencePropertyTest` pins decode → encode → decode
stability; `MatrixFixtureGeneratorTest` regenerates; `MatrixManifestTest.
canonicalFilesParseIntoTheirModelTypes` re-derives `MatrixCanonicals.streamChunks`
and asserts equality with the committed `canonical/stream.chunks.json` — a
record-shape change in `MatrixCanonicals` requires editing the canonical JSON, the
generator, and that assertion. Re-capture checklist: run `captureFixtures` with a key,
redact echoed keys to `<redacted>`, update the README provenance + frame counts,
re-run the full build.
